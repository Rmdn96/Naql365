## Findings to address after Lovable diff review

- **Theme consistency:** legacy Driver fields/cards/focus sections mix V2 semantic surfaces with older white/background rules. Retrofit route-scoped tokens while preserving intentional white signature canvas ink contrast.
- **Hierarchy:** the current dashboard is a simple vertical list. Improve reference/status/next-Stop grouping without inventing counts, schedule facts or suggested work.
- **Navigation:** public chrome and Driver navigation both expose locale context. Design compact Driver navigation using existing components; do not add another preference store or alter Auth routing.
- **Execution clarity:** keep existing one-action selection and authoritative clearance, but give it greater visual priority and preserve required instructions/error associations.
- **Feedback/connectivity:** existing retry/refresh and foreground tracking states must stay distinct from confirmed success. Do not imply offline synchronization.
- **Mobile/a11y:** inspect 360/390 primary actions, long Arabic addresses, details controls, signature/file fallback, focus, wrapping and contained secondary information before expanding to tablet/desktop.
- **Safety copy:** add concise AR/EN guidance to interact only while safely stopped, without changing a business predicate or disabling accepted functionality.

Important source reconciliation: the application already implements policy-authorized foreground location publication and stops its watch when the page is hidden. This is existing functionality, not a proposed Wave 5 GPS/background feature. Preserve its authority, policy, consent handling and visibility behavior unchanged.
