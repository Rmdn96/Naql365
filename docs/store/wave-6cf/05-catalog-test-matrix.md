## Independent connection protocol

CF29–CF36 must use at least two actual database connections and deterministic barriers around Store mutex/row-lock acquisition, not only Promise.all or sleep timing. Observe from a third independent connection after commit/abort. Assert row/event/receipt counts, selected version identity, private/public projections and no partial state. Expected outcomes are success+safe conflict/replay/denial according to intent, not two incompatible successes.

Use test-owned organizations and appropriate test-owned staff roles/grants in isolated reconstruction fixtures; existing role permissions are global, so do not mutate owner role grants in hosted acceptance. No Supabase fixture creation is authorized in this design gate. Build canonical scope fixtures only under future approved local test setup and roll back/clean exact owned rows. Test global uniqueness/scope swaps independently without claiming fixture bootstrap is a production configuration path.

## Publication and technical gate order

First approve exact design/grants, then implement/review SQL and run reconstruction/upgrade/RLS/concurrency/types. Migration-only success is not permission to expose public prices; legal/merchant/tax/delivery approvals still gate public publication. UI source inspection and a separate application port occur later, not to make SQL tests pass. All 42 case IDs must have reproducible results/evidence or an explicit unresolved blocker before the first slice can be called accepted.

Documentation-only validation now is format/link/credential-pattern/scope/migration checks, not any CF test PASS. No hosted catalog/price/payment acceptance or new exact-head application CI is claimed.
