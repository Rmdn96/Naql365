No migration numbers beyond the proposed first slice are assigned here. Re-evaluate then-current migration count before each future branch; immutable histories cannot be renumbered. Store remains inactive between technical slices; new tables or a nicer screen do not make payments eligible. There is no Guest, multi-supplier checkout, supplier portal, global KPI or Phase 8 slice authorized by this roadmap.

## Deliverable checklist for each future slice

- Pure schema/domain contract plus explicit safe DTO and failure semantics; reviewed allowlisted queries and effective permission map from the same organization context.
- New tables/functions/RLS only as separately approved; no changes to Transport pricing, immutable Quote/Order snapshots, Finance clearance, Driver/POD or Transport Guest capabilities.
- Unit/property tests for validators/money/transitions, SQL constraints/RLS/function grants, official DB types, independent connection races and exact-head repository CI. Existing database CI reconstructs migrations and compares generated types; it is future evidence only until actually run on that slice.
- Full relevant regression and build/lint/strict TS/format, tracked/history credential scans, scoped dependency review. Do not relabel old CI or application evidence as a new delivery commit's checks.
- Protected canonical Preview with exact application SHA and separate evidence HEAD, real bounded synthetic business fixtures, indexed visual evidence and independent cleanup. Failed/interrupted runs remain historical.

## Release controls and observability

Use server-authoritative Store activation bound to approved policy versions, never only a UI feature flag. Keep browse/publication, new placements, physical release and privileged money execution independently pausable. Pausing new commerce must preserve existing customer history, private authorized recovery, verified money facts and Finance reconciliation. Do not stop Transport because Store is paused.

Safe events include command category/result, organization/Market, aggregate revision, mutation correlation and duration. Do not log raw guest secrets, passwords, Auth cookies, provider credentials, private proof URLs, bank instructions or unrestricted customer contact. Reconciliation queue should expose actual unresolved receipt/execution facts to authorized Finance without fake global totals. No new monitoring backend or analytics infrastructure is implied.

Store success requires actual authoritative command outcomes and evidence, not lab-selected status screenshots. A shortage/delivery failure must remain recoverable by a case/refund/reconciliation workflow; the absence of warehouse stock counters is deliberate and does not justify deleting unsuccessful orders.
