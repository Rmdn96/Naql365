## Exact lab review procedure before any port

1. Read project metadata and exact source revision `64f7e4dc...`; obtain its complete parent-to-revision diff and full tree. If project HEAD is newer, inspect the accepted exact revision rather than treating latest as accepted. Record all added/modified/deleted files and dependency/config/knowledge changes.
2. Classify every changed file: visual component/style/copy; lab state/persona selector; mock product/business data; router/runtime; Auth/backend/provider/schema; dependency; knowledge/docs. Review transitive imports as well as visible page files.
3. Accept only compatible visual ideas after checking Egypt-only EGP, registered checkout, costs absent from customer DOM/serialized data, separate payment/fulfillment/settlement states, no stock/ETA/price/tax/legal claims. Owner-approved design does not approve business logic.
4. Reject TanStack/Vite route/runtime replacement, demo authority, fake command success, computed mock money, live destinations, guest security shortcuts, independent theme persistence, unapproved dependencies/backend integrations. Lab selectors/placeholders stay clearly lab-only; no canonical import or code path.
5. Preserve Waves 1–5 and accepted application behavior; future code ports use typed Store contracts and existing Next.js architecture. Read bundled installed Next.js docs before code changes, as AGENTS.md requires. All schema/command work still needs separate approval.
6. Record exact source path/hash, intended target, retained visual portion, discarded logic and integration tests per file. A generated summary is not a diff review. Any actual backend need returns to its separately approved schema/contract slice.
