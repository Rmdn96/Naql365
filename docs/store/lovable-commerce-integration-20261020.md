## Implemented behavior

The homepage prominently links Transport and Store, searches the real catalog and displays at most four products from the existing approved public projection. Category links use the existing server query. A paused/unapproved Store displays localized non-purchasable content with no invented products/prices.

Homepage and catalog Add to cart use `/api/store` and the existing authoritative cart RPC. Requests carry listing versions, quantities, cart revision and mutation identity; no customer identity, supplier entitlement or client total becomes authority. Edits in one tab are serialized, double clicks are synchronously locked, and unknown outcomes retain their exact mutation for an explicit replay. Database revision/idempotency rules still arbitrate other tabs/devices. Definitive conflicts produce feedback rather than automatic retries.

The badge sums authoritative quantities after mutation, navigation, refresh and window focus. A guest receives the canonical login route without a phantom cart. Errors are distinct from an empty confirmed cart. Cart quantity editing and item removal persist through the server. A consumed checkout cart renders empty/read-only with the order-history link; a later addition starts a new active cart rather than carrying historical order items forward. No browser storage or optimistic totals establish commercial authority.

Existing registered checkout, product details/media, independent Store order history, Customer workspace and governed Staff catalog administration are reused. Future product creation still uses Migration 51 administration, not source-code edits. No second backend, tables or permissions were introduced.

Transport CTA remains `/{locale}/request`, using the accepted wizard. WhatsApp remains the existing configured `whatsappUrl(country, locale)` helper, independently of booking; no number was invented or changed. Existing EG default/Cairo coverage and valid SA/EG preference behavior remain intact. Saudi commercial activation was not changed.

The existing three-price separation, supplier fulfillment, immutable order snapshots, Finance receipt verification and mixed collection/settlement contracts are unchanged. Only the public retail projection enters homepage product props. Supplier reference/cost/margin fields and private payment evidence are not added to customer HTML, metadata or search.
